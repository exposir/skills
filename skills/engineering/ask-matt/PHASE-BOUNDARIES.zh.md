# 阶段边界

一个**阶段**（phase）是会话内的一块工作：访谈、实现、QA。这个定义故意保持模糊：当你觉得"好了，这块做完了"的时候，一个阶段就结束了。

**阶段边界**是两个阶段之间的空隙，也是这个决定唯一该出现的地方。阶段中途没有决定可做：继续，或者把剩下的工作拆给子代理。中途压缩上下文会让 agent 丢掉线索。

## 五个选项

| 选项 | 作用 |
| ------------ | --------------------------------------------------------------- |
| **继续** | 留在当前会话。完全不做上下文切换。 |
| **`/clear`** | 清空上下文窗口，从零开始。 |
| **`/handoff`** | 写一个可移植的 markdown 文件，用它随处开新会话。 |
| **子代理** | 把任务送进它自己的上下文窗口，拿回一份报告。 |
| **`/compact`** | 压缩当前上下文，用摘要开一个新会话。 |

## 决策树

在边界处自上而下走。第一个**是**胜出。

**1. 你能在当前会话里继续吗？** 两件事让答案是"是"：下一阶段需要这一阶段作为**一手来源**，或者剩下的[智慧区](https://www.aihero.dev/ai-coding-dictionary/smart-zone)（约 150k token）足够装下下一阶段。访谈到实现是标准的"是"：实现要的是推理的原文，而不是它的摘要。继续不花成本、不丢东西，所以先从它看起，确定不能继续才往下走。

**2. 上下文与接下来要做的事无关吗？** 这个会话里的一切（探索、决定、死胡同）是否都可丢弃？如果是，**`/clear`**。它是棋盘上最便宜的一步：不花时间，还回整个窗口。`/clear` 也不是终点：旧会话仍可恢复。

做错这一步的代价是单向的。清掉一个*相关*的上下文，你就丢掉了所构建之物的**为什么**，事后读多少遍 diff 都找不回来。

**3. 需要交接吗？** `/handoff` 适用范围窄。只有这些情况需要它：

- 换到**新 harness**（Claude 换 Codex），
- 搬到**新目录**或新仓库，
- 把工作发给**同事**，
- 或者**阶段中途**分叉一个边任务，同时不打断手头的事。

这个清单就是全部条款。`/handoff` 买到的是**可移植性**：一份可以带走的文件。如果没有任何东西要走动，你就不需要它。

**4. 任务能离开键盘完成吗？** 范围是否收得足够紧，不需要你盯着、不需要引导？那就交给**子代理**，当前会话不动。自动审查是标准案例：agent 读 diff 然后报告，期间不需要你。

**5. 否则，`/compact`。** 上下文相关、同一 harness、同一目录、而且你需要留在回路里：这就是决策树落地的位置，而且经常落在这里。给它一条指令（`/compact 我们接下来要 QA 这一块`），让摘要保住下一阶段需要的东西。

`/compact` 是**默认项，不是第一反应**。它待在树底，因为上面四个问题要么更便宜、要么更精确。人们一上来就用它时的失败模式是：开出一个新会话，对被摘要压平的某个决定自信地犯错。

## 一手来源与二手来源

除了**继续**，每一步都把**一手来源**变成**二手来源**：会话本身的样子，被它的摘要取代。这笔交易永远是同一个形状：

| 来源 | 信息 | 噪音 | 活动空间 |
| --------------------------------- | ----------- | ----- | ------------ |
| 一手（继续） | 完整 | 多 | 小 |
| 二手（`/compact`、`/handoff`） | 有损 | 少 | 大 |

这就是问题 1 排在最前的原因。只有当留在原地比省下来的更贵时，你才付出有损的代价。

## 这些都是判断

这些问题不是客观的：每个都带口味，同一个边界在不同日子可能走向两个方向。价值在于**按顺序**问它们，在边界处问，而不是在工作中间问。

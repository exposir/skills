# 界面原型

在同一条路由上出**好几个结构完全不同的界面方案**，一条悬浮底栏来回切。用户在浏览器里翻，挑一个（或每个里偷点），剩下全扔。

如果问的是逻辑/状态而不是长相，走错路了。去 [LOGIC.zh.new.md](LOGIC.zh.new.md)。

## 什么时候该走这条路

- "这页面该长什么样？"
- "定稿前我想先看这仪表盘的几个方案。"
- "设置页换个布局试试。"
- 任何用户本来要在脑子里三个模糊线稿之间纠结一整天的时刻。

## 两种落法：强烈偏好第一种

界面原型**贴着实跑的应用**时最好判断：真页头、真侧栏、真数据、真密度。孤零零的一次性路由是真空：什么方案孤立地看都挺好。只要有现成页面能装下方案，就落第一种。原型真没地方住才用第二种。

### 落法一：改现有页面（首选）

路由已经有了。方案渲染在**同一条路由**上，靠 `?variant=` 查询参数切换。已有的取数、参数、鉴权原样保留。只有渲染部分换掉。这是默认，没有具体理由就选它。

如果原型对象还没页面、但_天生该住进某个页面里_（仪表盘的新区块、设置页的新卡片、现有流程的新步骤），照样是落法一。方案挂进宿主页面。

### 落法二：新开页面（最后手段）

只有被原型的东西真没有现成页面可住时才用（比如全新顶层界面，或哪都嵌不进去的流程）。

**开一条一次性路由**，沿用项目已有的路由习惯。别发明新顶层结构。名字起得一眼像原型（路径或文件名里带 `prototype`）。还是同一套 `?variant=`。

选落法二之前先问自己一句：真没有现成页面能嵌？空路由会把设计问题藏起来，有人的路由才会把它们逼出来。

两种落法的悬浮底栏完全一样。

## 怎么做

### 1. 写清问题、定个数

默认 **3 个方案**。超过 5 个就不再是"完全不同"而是噪音，5 个封顶。

计划写一行，放在原型所在地或文件顶部注释：

> "设置页三个方案，`?variant=` 切换，落在现有 `/settings` 路由上。"

用户在不在场反驳，这一行都有用。

### 2. 出结构完全不同的方案

每个方案都得经得起三问：

- 页面的目的和它能拿到的数据。
- 项目的组件库 / 样式体系（TailwindCSS、shadcn、MUI、裸 CSS，有啥用啥）。
- 一个明确的导出组件名，比如 `VariantA`、`VariantB`、`VariantC`。

方案必须**结构不同**：布局不同、信息层级不同、主交互控件不同，光颜色不同不算。三张微调过的卡片网格不是界面原型，是壁纸。两个草稿长太像，就带着"明令禁止卡片网格"重画其中一个。

### 3. 接起来

路由上放一个切换器组件：

```tsx
// 伪代码，按项目框架改
const variant = searchParams.get('variant') ?? 'A';
return (
  <>
    {variant === 'A' && <VariantA {...data} />}
    {variant === 'B' && <VariantB {...data} />}
    {variant === 'C' && <VariantC {...data} />}
    <PrototypeSwitcher variants={['A','B','C']} current={variant} />
  </>
);
```

落法一（现有页面）：所有现有取数都留在切换器上面，每个方案只换渲染子树。

落法二（新页面）：`/prototype/<name>` 下的一次性路由挂同一个切换器。

### 4. 搭悬浮切换条

屏幕底部居中一条固定定位小栏，三样：

- **左箭头**：上一个方案（循环）。
- **方案标签**：显示当前方案的键，方案导出了名字就连名字一起，比如 `B (Sidebar layout)`。
- **右箭头**：下一个（循环）。

行为：

- 点箭头改 URL 查询参数（用框架路由，如 Next 的 `router.replace`、React Router 的 `navigate`），方案可分享、刷新不丢。
- 键盘 `←` `→` 也能切。焦点在 `<input>`、`<textarea>` 或 `[contenteditable]` 里时别抢方向键。
- 视觉上跟页面分得清（高对比胶囊、轻微阴影），让人一眼看出它不是被评估的设计的一部分。
- 生产构建里藏掉：用 `process.env.NODE_ENV !== 'production'` 之类的门挡住，防止原型误合并把底栏带上线。

切换条放单个共享组件里，两种落法共用。放在项目里共享 UI 该待的位置。

### 5. 交出去

把 URL（和 `?variant=` 的键）给人。用户得空自己翻。值钱的反馈通常是**"我要 B 的页头配上 C 的侧栏"**：那才是他们真正想要的设计。

### 6. 存答案、清场

有方案胜出后，先存答案（哪个方案、为什么），再按 [SKILL.zh.new.md](SKILL.zh.new.md) 的路子存原型。胜者折进真实代码，其余挪去一次性分支，别进主干：

- **落法一**：胜者折进现有页面；败者和切换器从主干拿掉。
- **落法二**：胜出方案升格成真路由；一次性路由和切换器从主干拿掉。

方案全集是一手来源，所以进一次性分支，不进垃圾桶：留在主干上的方案组件和切换器烂得快，还坑下一位读代码的人。

## 别干的事

- **只差颜色或文案的方案。** 那是微调，不是原型。真方案在结构上就互不买账。
- **方案之间共享太多代码。** 共享 `<Header>` 没事；共享 `<Layout>` 就把本意废了。每个方案都得能自由扔掉布局。
- **把方案接到真实写操作上。** 只读原型没问题。方案要改数据就指到桩上：问的是"这该长什么样"，不是"后端通不通"。
- **把原型直接升格上线。** 方案代码是在原型约束下写的（没测试、错误处理能省则省）。折进去时正经重写。

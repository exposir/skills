# 原型

原型就是**用完即扔的代码，用来回答一个问题**。问的是什么，就长成什么样。

## 先分路

先搞清楚要回答哪个问题。看用户的提示词、看周边代码，用户在就直接问：

- **"这逻辑 / 状态模型靠不靠谱？"** → 走 [LOGIC.zh.new.md](LOGIC.zh.new.md)。做一个能发出去的单个 HTML 文件，有自由点着玩的按钮，也有分标签的引导演示，把状态机硬推到那些纸上推不动的场景里去，而且非程序员也能上手。
- **"这界面该长啥样？"** → 走 [UI.zh.new.md](UI.zh.new.md)。同一条路由上出好几个结构完全不同的界面方案，URL 参数切换，底部一条悬浮栏来回翻。

两条路做出来的东西天差地别，走错了整个原型就废了。如果问题真含糊、用户又不在，就默认选跟代码更搭的那条（后端模块 → 逻辑；页面或组件 → 界面），并且把假设写在原型最顶上。

## 两条路都守的规矩

1. **从头就是一次性的，还得写在脸上。** 原型代码放在它将来真要被用到的位置旁边（挨着它为之做原型的模块或页面），上下文一目了然，但名字要起得让路人一眼认出这是原型、不是生产代码。一次性界面路由沿用项目已有的路由习惯，别发明新顶层结构。
2. **跑起来要零脑子。** 界面原型是任务运行器里一条命令的事：`pnpm <name>`、`python <path>`、`bun <path>`，都行。逻辑演示就是双击即开的单个 HTML。启动这件事上不许让人思考。
3. **默认不留数据。** 状态都在内存里。持久化恰恰是原型要_检验_的东西，不是它该依赖的东西。问题真要碰数据库，就用草稿库或本地文件，名字起成"PROTOTYPE，用完删我"这种。
4. **不抛光。** 不写测试，错误处理只做到"能跑"为止，不搞抽象。目的是快点学到东西。
5. **状态摆上台面。** 每做一个动作（逻辑）或每切一次方案（界面），把完整相关状态打印或渲染出来，让人看见到底变了什么。
6. **收尾要存档。** 验证通过的决策折进真实代码；原型本身当**一手来源**收起来：提交到主干之外的一次性分支，实现 issue 上留个指向它的指针。答案（结论 + 它答掉的问题）也写进 issue 或 commit。主干只留验证过的决策。

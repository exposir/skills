一个模糊的想法出现了，太大，一个 agent 会话装不下，而且裹在迷雾里：从这到**目的地**的路还看不见。寻路就是找到那条路，而不是冲向目的地。本 skill 把这条路画成仓库 issue tracker 上的一张**共享地图**，然后一张一张地解决它的**决策工单**（其解决结果是一个决策，而不是一段要执行的构建切片），直到路线清晰。

目的地因每次努力而异，命名它是画图的第一步：它塑造每一张工单。它可能是一个要交接并迭代的规格、一个要在规划开始前锁定的决策，或一个像数据结构迁移一样就地完成的变更。地图是领域无关的：工程工作、课程内容，任何符合这个形状的都行。

## 规划，不要执行

寻路默认是**规划**：每张工单解决一个决策，当地图上的路清晰时地图就算完成，在有人去执行之前没有剩下任何需要决定的东西。想直接做事的冲动通常是你已经到达地图边缘的信号，该交接了。一次努力可以在其**Notes** 中覆盖这一点，把执行带进地图本身，但如果没有，就产出决策，不是交付物。

## 用名字引用

每一张地图和工单都是一个 issue，所以它有一个**名字**：它的标题。在人类阅读的所有东西中（叙述、地图的 Decisions-so-far），用名字引用它，绝不用裸 id、编号或 slug。一堵 `#42, #43, #44` 是不可读的；名字一眼就能扫。id 和 URL 不会消失；名字包裹着链接，但它们藏在名字*里面*，绝不代替名字。

## 地图

地图是仓库 issue tracker 上的一个 issue，标记为 `wayfinder:map`，是规范产物。它的工单是地图的子 issue。

地图是一个**索引**，不是存储。它列出已做出的决策，并指向持有其细节的工单；一个决策只存在于一个地方，它的工单，所以地图从不重述它，只做要点摘要并链接。

**地图、其子工单、阻塞关系和前沿查询实际住在哪里，取决于 tracker。** issue tracker 应该已经提供给你了。如果没有，让用户运行 `/setup-matt-pocock-skills`。查阅 tracker 文档的"寻路操作"部分，了解*这个*仓库如何表达它们。如果没有提供 tracker，默认使用本地 markdown tracker。

### 地图正文

整张地图的低分辨率视图，每会话加载一次。打开的工单**不**列出：它们是打开的子 issue，通过查询找到。

```markdown
## 目的地

<这张地图的终点是什么样子：这次努力正在寻找通往的规格、决策或变更。一两行；每个会话在选工单之前都先朝向它。>

## Notes

<领域；每个会话应查阅的 skill；本次努力的固定偏好>

## 已做出的决策

<!-- 索引：每行一条已关闭的工单，足以判断相关性，然后放大链接看工单持有的细节 -->

- [<已关闭工单标题>](link)：<答案的单行摘要>

## 尚未指定

<!-- 见"战争迷雾"：你还不能开成工单的范围内迷雾；随着前沿推进而升级 -->

## 范围之外

<!-- 见"范围之外"：被判定超出目的地的工作；已关闭，永不升级 -->
```

### 工单

每张工单是地图的一个**子 issue**；tracker 的 issue id 是它的身份标识。它的正文是问题，大小适配一个 100K token 的 agent 会话：

```markdown
## 问题

<本工单所解决的决策或调查>
```

每张工单携带一个 `wayfinder:<type>` 标签，类型为 `research`、`prototype`、`grilling`、`task` 之一（见[工单类型](#工单类型)）。

一个会话通过**先**将工单分配给驱动地图的开发者来**认领**它，在任何工作之前，这样并发会话会跳过它。分配人*就是*认领：一张打开、未分配的工单就是未认领的。

阻塞使用 tracker 的**原生**依赖关系：至关重要，因为它把前沿*可视化*地呈现在 tracker 自己的 UI 里，人不用打开地图就能看到什么可拿。只有不存在原生阻塞的 tracker 才回退到正文约定。一张工单在其所有阻塞工单都关闭时是**未阻塞**的；**前沿**是打开的、未阻塞的、未认领的子工单，是已知的边缘。

答案不属于工单正文；它在解决时记录（见[遍历地图](#遍历地图)）。解决工单时创建的资产从 issue 链接，不粘贴进去。

## 工单类型

每张工单要么是 **HITL**（人在回路中，与一个为自己说话的人类*一起*工作），要么是 **AFK**，由 agent 独立驱动。一张 HITL 工单只有通过那种实时交流才能解决；agent 绝不能代替人类一侧（一个自问自答的拷问 agent 已经打破了这个规则）。

- **Research**（AFK）：阅读文档、第三方 API 或知识库等本地资源，以暴露一个决策等待的事实。由一个调用 Skill 工具参数为 "research" 的子代理解决。当需要当前工作目录之外的知识时使用。
- **Prototype**（HITL）：通过制作一个廉价、粗略、具体的产物来提高讨论的保真度，让人对它做出反应（大纲、粗略尝试、桩或 UI/逻辑代码），通过调用 Skill 工具参数为 "prototype"。把原型作为资产链接。当"应该长什么样"或"应该怎么运作"是核心问题时使用。
- **Grilling**（HITL）：对话。默认情况。总是调用 Skill 工具两次，参数分别为 "grilling" 和 "domain-modeling"。
- **Task**（HITL 或 AFK）：在*决策*可以做出之前必须完成的手动工作：没有要决定、构造或研究的东西，但讨论被它阻塞，直到它完成。注册服务以便判断其 API、开通访问权限、移动数据以便看到其形状。这是唯一一个*做*而不是决定的类型，它通过解除一个决策的阻塞来赢得自己的位置，而不是通过交付目的地。agent 在能独自驱动时（AFK）驱动它；否则给人类一份精确的清单（HITL）。当工作完成时解决；答案记录做了什么以及任何最终事实（凭证位置、新 URL、行数），后续工单依赖这些。

## 战争迷雾

地图是*刻意*不完整的：不要画你还看不见的东西。在活的工单之外是**战争迷雾**：你能感觉到即将到来但还无法确定的决策和调查的模糊视图，因为它们悬在仍然开放的问题上。解决一张工单会清除它前面的迷雾，将现在可以指定的东西升级为新的工单，一次一张，直到通往目的地的路清晰，不再有工单。

地图的**尚未指定**部分就是写下这个模糊视图的地方：被怀疑的问题，以后要重新访问的区域。它是朝向目的地的*尚未被发现的前沿*：这里的一切都在范围内，只是还不够清晰到可以开成工单。按视图允许的松散或完整程度来写；它同时作为协作者的指路牌，让人看到这次努力正朝哪个方向走。

**迷雾还是工单？** 测试标准是：你现在能否精确陈述问题，而不是你现在能否回答它。

- **开工单**当问题已经很清晰，即使它被阻塞、你还不能对它行动。
- **尚未指定**当你还不能那么清晰地表述它。不要把迷雾预先切成工单大小的块：它比工单更粗，一片迷雾可能在前沿到达它时升级为好几张工单，或者零张。

**尚未指定**不包括已经决定的（Decisions so far）、已经活的工单以及范围之外的东西（下一节）。

## 范围之外

迷雾只聚集在*朝向*目的地的方向。目的地固定了范围，所以超出目的地的工作是**范围之外**：它不是迷雾，也不属于**尚未指定**。它在地图上有自己的**范围之外**部分：你已有意识地排除出*这次*努力的工作。让它落在这里的是范围，不是清晰度。

范围之外的工作永远不升级（前沿停在目的地），所以它只在目的地被重新绘制时才会回来，而且那时是一次新的努力，不是恢复。

把某件事判定为范围之外是一个范围划定行为，不是路线上的一个步骤。当一张已经存在的工单被证明坐在目的地之外（在画图时范围划错了，或被某个解决方案暴露出来），**关闭它**（一张关闭的工单明确地离开了前沿），并在**范围之外**部分留一行：要点摘要加上为什么它超出范围，链接到已关闭的工单。它不进入**已做出的决策**，后者记录的是实际走过的路线；一个范围边界不是路线上的一个步骤。

## 调用

两种模式。无论哪种，**每个会话绝不超过一张工单**，除非是 research 工单。

### 画地图

用户带着一个模糊的想法调用。

1. **命名目的地。** 调用 Skill 工具两次，参数分别为 "grilling" 和 "domain-modeling"，确定这张地图在寻找通往什么：规格、决策或变更。目的地固定了范围，所以先敲定它。
2. **画出前沿。** 再次拷问，这次**广度优先**：在整个空间展开，而不是在任何一条线上深挖，浮现出开放的决策和现在就能迈出的第一步。**如果这没有浮现出任何迷雾**（通往目的地的路已经清晰，整个旅程小到一次会话能装下），你不需要地图。停下来，问用户想怎么继续。
3. **创建地图**（标记 `wayfinder:map`）：目的地和 Notes 填好，已做出的决策为空，迷雾草绘进**尚未指定**。
4. **创建你现在能指定的工单**作为地图的子 issue，然后在**第二遍**中连接阻塞边（issue 需要 id 才能互相引用）。连接把它们排成前沿和被阻塞的；你暂时还不能指定的都留在迷雾里：**尚未指定**部分。
5. **启动 research 子代理。** 对于你刚刚创建的每张 `research` 工单，启动一个调用 Skill 工具参数为 "research" 的子代理来并行解决，在一次性 `research/<name>` 分支上捕获其发现，从工单留一个上下文指针。
6. 停止：画图是一个会话的工作；它不亲手解决任何东西。

### 遍历地图

用户带着一张地图调用（URL 或编号）。工单是**可选的**：没有时，你来选下一个决策，不是用户。

1. 加载**地图**：低分辨率视图，不是每张工单的正文。
2. 选择工单。如果用户指定了，用它。否则按顺序取第一张前沿工单。**认领它**：在任何工作之前把它分配给你自己。
3. 解决它。**按需放大**：按需获取任何相关或已关闭工单的完整正文；调用 Skill 工具，参数为 `## Notes` 块中列出的 skill。如果不确定，调用 Skill 工具两次，参数分别为 "grilling" 和 "domain-modeling"。
4. 记录解决方案：将答案作为**解决方案评论**发布，**关闭** issue，并向地图的 Decisions-so-far 追加一条**上下文指针**。
5. 添加新浮现的工单（创建再连线）；将答案已使其可指定的任何迷雾升级，从**尚未指定**中清除每片已升级的迷雾，使其只作为其新工单存在。如果答案揭示了某张工单（这张或另一张）坐在目的地之外，**把它判定为范围之外**，而不是在路线上解决它。如果这个决策使地图的其他部分失效，更新或删除那些工单。

用户可能并行运行未被阻塞的工单，所以预期其他会话也在并发编辑 tracker。

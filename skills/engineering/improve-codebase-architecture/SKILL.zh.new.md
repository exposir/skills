# 改进代码库架构

找到架构摩擦，提出**深化机会**：把浅模块变成深模块的重构。目标是可测试性，以及让 AI 能顺畅导航你的代码。

本命令扎根于项目的领域模型，建立在共享设计词汇上：

- 调用 Skill 工具参数为 "codebase-design" 拿架构词汇（**模块**、**接口**、**深度**、**接缝**、**适配器**、**杠杆**、**局部性**）和原则（删除测试、"接口就是测试面"、"一个适配器 = 假接缝，两个 = 真"）。每个建议照用这些词，别滑到"组件"、"服务"、"API"、"边界"。
- `CONTEXT.md` 的领域语言给你好的接缝名字；`docs/adr/` 里的 ADR 记了本命令不该重翻的旧账。

## 流程

### 1. 探索

**先定范围再扫：YAGNI。** 深化一个模块值不值，看的是未来对它改起来省不省事，所以最近改得多的代码多给一些权重。在看之前先决定*在哪*看：

- 用户指定了方向（一个模块、一个子系统、一个痛点），直接用，跳过下面的推断。
- 否则，往回翻一大段提交历史（`git log --oneline`），找代码库的热点，反复出现的文件和区域，让这些路径先吸走你的注意力。如果变更散落、没有明显热点，就把网撒大。

先读项目的领域术语表（`CONTEXT.md`）和所涉区域的任何 ADR。

然后派一个子代理去遍历代码库。别按死板启发式来；有机地走，注意你在哪感觉到摩擦：

- 在哪理解一个概念需要在很多小模块之间跳来跳去？
- 哪些模块是**浅的**，接口几乎和实现一样复杂？
- 哪些纯函数只是为了可测试性被抽出来，但真正的 bug 藏在它们被调用的方式里（没有**局部性**）？
- 哪些紧耦合的模块跨接缝泄漏？
- 代码库的哪些地方没测，或者通过当前接口很难测？

对你怀疑浅的任何东西用**删除测试**：删掉它，复杂度是集中了还是只是搬家了？"是，集中了"就是你要的信号。

### 2. 以 HTML 报告呈现候选

写一个自包含 HTML 文件，丢到操作系统临时目录，仓库里不落东西。从 `$TMPDIR` 取临时目录，回退到 `/tmp`（Windows 用 `%TEMP%`），写到 `<tmpdir>/architecture-review-<timestamp>.html`，每次跑都是新文件。帮用户打开它（Linux 用 `xdg-open <path>`，macOS 用 `open <path>`，Windows 用 `start <path>`），并告诉用户绝对路径。

报告用**Tailwind CDN** 做布局和样式，**Mermaid CDN** 画图，用来画关系是图/流/序列形状的地方。Mermaid 和手工 CSS/SVG 混着用：图状关系（调用图、依赖、序列）用 Mermaid，更编辑性的效果（质量图、横截面、折叠动画）用手工 div/SVG。每个候选给一个**前后对照可视化**。要有视觉冲击。

每张候选卡片包含：

- **文件**：涉及哪些文件/模块
- **问题**：为什么当前架构引起摩擦
- **解决方案**：纯英语说变什么
- **收益**：用局部性和杠杆解释，测试怎么变好
- **前后对照图**：并排，手工画，展示浅度和深化
- **推荐强度**：`Strong`、`Worth exploring`、`Speculative` 之一，渲染成徽章

报告以**首要推荐**收尾：你会先干哪个候选，为什么。

**用 CONTEXT.md 的词汇讲领域，用 `/codebase-design` 的词汇讲架构。** CONTEXT.md 定义了 "Order"，就谈 "Order 入口模块"，不是 "FooBarHandler"，也不是 "Order 服务"。

**ADR 冲突**：候选跟现有 ADR 矛盾，只有摩擦真大到值得重开 ADR 时才亮出来。卡片里清楚标（比如琥珀色警告框："与 ADR-0007 矛盾，但值得重开，因为……"）。别列 ADR 禁止的每个理论重构。

见 [HTML-REPORT.zh.md](HTML-REPORT.zh.md) 拿完整 HTML 脚手架、图表模式和样式指南。

**此时不要提接口。** 文件写完后，问用户："你想探索哪一个？"

### 3. 拷问循环

用户选了候选后，调用 Skill 工具参数为 "grilling"，跟他们走决策树：约束、依赖、深化模块长什么样、接缝后面放什么、哪些测试活下来。

决策结晶的时候，副作用内联发生；调用 Skill 工具参数为 "domain-modeling" 保持领域模型最新：

- **给深化模块起了一个 `CONTEXT.md` 里不存在的概念名？** 加进 `CONTEXT.md`。文件不存在就惰性创建。
- **对话中打磨了一个模糊术语？** 当场更新 `CONTEXT.md`。
- **用户以一个承重的理由毙了候选？** 提议 ADR，话说成这样："要我把这记成 ADR 吗，这样以后架构审视不会重新提出来？"只有当未来探索者确实需要这个理由来避免重提时才提议；跳过短暂的理由（"现在不值得"）和自明的理由。
- **想探索深化模块的替代接口？** 调用 Skill 工具参数为 "codebase-design"，用它那个 design-it-twice 的并行子代理模式。

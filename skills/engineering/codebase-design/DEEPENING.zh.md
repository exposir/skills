# 深化

如何在给定依赖的情况下，安全地深化一组浅模块。假定使用 [SKILL.zh.md](SKILL.zh.md) 中的词汇：**模块**、**接口**、**接缝**、**适配器**。

## 依赖类别

评估一个深化候选时，对其依赖进行分类。类别决定了深化模块如何跨接缝测试。

### 1. 进程内

纯计算、内存状态、无 I/O。始终可深化：合并模块，通过新接口直接测试。不需要适配器。

### 2. 本地可替换

有本地测试替身的依赖（PGLite 替代 Postgres、内存文件系统）。如果替身存在则可深化。深化模块在测试套件中用运行中的替身来测试。接缝是内部的；在模块的外部接口处没有端口。

### 3. 远程但自有（端口与适配器）

跨网络边界的自有服务（微服务、内部 API）。在接缝处定义一个**端口**（接口）。深模块拥有逻辑；传输层作为**适配器**注入。测试使用内存适配器。生产使用 HTTP/gRPC/队列适配器。

推荐形状：*"在接缝处定义一个端口，为生产实现 HTTP 适配器，为测试实现内存适配器，这样逻辑尽管跨网络部署，但住在一个深模块里。"*

### 4. 真正外部（Mock）

不受你控制的第三方服务（Stripe、Twilio 等）。深化模块将外部依赖作为注入端口接受；测试提供一个 mock 适配器。

## 接缝纪律

- **一个适配器意味着假设的接缝。两个适配器意味着真实的接缝。** 除非至少有两个适配器是合理的（通常是生产 + 测试），否则不要引入端口。单适配器接缝只是间接层。
- **内部接缝 vs 外部接缝。** 一个深模块可以有内部接缝（对其实现私有，由它自己的测试使用），也可以有接口处的外部接缝。不要因为测试使用了内部接缝，就把它通过接口暴露出去。

## 测试策略：替换，不要分层

- 对浅模块的旧单元测试，一旦在深化模块的接口处有了测试就变成废物；删除它们。
- 在深化模块的接口处写新测试。**接口就是测试面。**
- 测试断言通过接口的可观察结果，不是内部状态。
- 测试应该在内部重构中存活，因为它们描述的是行为，不是实现。如果测试在实现变更时必须跟着变，它就在测到接口后面去了。

# MISSION.md 格式

`MISSION.md` 放在工作区根目录。它记录用户学习这个主题的_原因_。每个教学决策（接下来教什么、展示哪些资源、设计哪些练习）都应该追溯回这份文档。

## 模板

```md
# 使命：{主题}

## 为什么
{1-3 句话。用户正在追逐的具体现实世界目标。当他们拥有这项技能时，他们的生活或工作会发生什么变化？避免"理解 X"这类抽象表述；追问底层的成果。}

## 成功的样子
- {一件用户将能做到的、具体的、可观察的事}
- {另一件具体的事}
- {……}

## 约束
- {时间、预算、已有承诺、学习偏好，任何限制方法的东西}

## 范围之外
- {用户明确不想现在追的邻近主题，保护最近发展区}
```

## 规则

- **一个工作区一个使命。** 如果用户想学两件不相关的事，那就是两个工作区。
- **具体胜过抽象。** "十月前跑完半马"胜过"更健康"。"给团队交付一个 Rust CLI"胜过"学 Rust"。
- **推动拒绝模糊。** 如果用户说不清为什么，在写任何东西之前先访谈他们。一个烂使命比没有使命更糟。
- **现实变化时修订。** 使命会变。当用户的目标移动时，更新这个文件：不要让一个过时的使命指引未来的会话。
- **保持简短。** 如果 `MISSION.md` 超过一屏，它就不再是指南针，而是计划了。

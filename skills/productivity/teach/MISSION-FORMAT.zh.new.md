# MISSION.md 格式

`MISSION.md` 放在工作区根目录。记的是用户为什么学这个。每个教学决策（教什么、展示什么资源、设计什么练习）都得能追溯到这。

## 模板

```md
# 使命：{主题}

## 为什么
{1-3 句话。用户追的那个具体现实目标。有了这项技能，他生活或工作里什么会变？别写"理解 X"，追问到底层成果。}

## 成功的样子
- {一件具体的、可观察的事，用户能做到}
- {另一件}
- {……}

## 约束
- {时间、预算、已有承诺、学习偏好，任何限制方法的东西}

## 范围之外
- {用户明确不想现在追的邻近主题，保护最近发展区}
```

## 规矩

- **一个工作区一个使命。** 两件不相关的事，两个工作区。
- **具体赢抽象。** "十月前跑完半马"赢"变健康"。"给团队交付一个 Rust CLI"赢"学 Rust"。
- **模糊就追问。** 用户说不清为什么，先访谈，别急着写。烂使命不如没使命。
- **现实变了就改。** 使命会变。目标动了，更新文件，别让过时的使命指挥后面的课。
- **别写长。** 超过一屏，就不是指南针，是计划了。

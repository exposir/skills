# 学习记录格式

学习记录放在 `./learning-records/` 里，按顺序编号：`0001-slug.md`、`0002-slug.md`，以此类推。惰性创建目录：只在写第一条记录时才建。

它们是教学版的 ADR：记录不那么明显的经验教训、关键洞察和已声明的先前知识，这些东西会指引未来的会话。用来计算最近发展区。

## 模板

```md
# {学到或确立的短标题}

{1-3 句话：学到了什么（或确立了什么先前知识），以及为什么它对未来会话重要。}
```

这就是全部格式。学习记录可以只有一个段落。价值在于记录_这个_现在已经知道了，以及_为什么_它改变了接下来该教什么，而不在于填满各个章节。

## 可选章节

只在它们真正增加价值时才加。大多数记录不需要。

- **Status** frontmatter（`active | superseded by LR-NNNN`）：当早期的理解后来被证明是错的并被替换时有用。
- **Evidence**（证据）：用户如何展示了这个理解（回答了一个问题、完成了一个练习、引用了先前经验）。当这个主张可能被重新审视时有用。
- **Implications**（影响）：这对未来的会话解锁了什么或排除了什么。不明显时值得记录。

## 编号

扫描 `./learning-records/`，找到最大的已有编号，加一。

## 什么时候写学习记录

当以下任一为真时写：

1. **用户展示了对某个非平凡东西的真正理解**：不仅仅是接触，而是有证据表明他们能正确使用这个概念。这为接下来教什么设定了一个新底线。
2. **用户透露了先前知识**："我已经知道 X。"记下来，这样未来的会话不会重复教。同时记录声明的_深度_。
3. **一个误解被纠正了**：用户之前相信了错误的东西，现在明白了为什么。这些价值很高：它们能预测相关主题未来的绊脚石。
4. **使命因学习而发生转变**：用户发现他们关心的东西和他们想的不一样。交叉链接到 [[MISSION.md]] 并更新它。

### 什么不算

- 只是过了一遍的材料。过一遍不算学习。等证据出现。
- 已经在 [[GLOSSARY.md]] 里简洁记录为术语定义的东西。不要重复。
- 逐会话的活动日志。学习记录不是日记：它们是决策级洞察。

## 取代

当后来的记录与早期记录矛盾时（用户的理解深化或纠正了），把旧记录标记为 `Status: superseded by LR-NNNN`，而不是删除它。理解如何演化的历史本身就是有用的信号。
